# Troubleshooting

## The golden test fails after a source change

`test/anki-apkg-export.test.ts` asserts byte equality against
`test/fixtures/output.apkg`, so any change to what the exporter or template
writes fails it by design.

Checks:

- Read the diff the failure prints. It shows the SQL the template produced, so
  the changed field is usually visible directly.
- Confirm the change was intended and is not an accidental widening.

Fix:

- `pnpm run fixture:regen`, committed **in the same commit** as the change.
- If the change was not intended, revert it rather than adopting the fixture.

## Two identical calls produce different bytes

Every export stamps its own build time into `col.mod`, `col.scm`, `col.crt`, and
the deck and notetype `mod` fields, so two calls a millisecond apart legitimately
differ. Byte reproducibility is a guarantee for the _same_ export, not across
separate ones.

Checks:

- In tests, pin the clock: `vi.useFakeTimers({ now, toFake: ["Date"] })`.
- Across machines, differing bytes for the same pinned clock is a real bug —
  something is reading a local rather than UTC clock.

Fix:

- Pin the clock in the test.
- For a genuine cross-machine difference, look at `toArchiveClock` in
  `src/exporter.ts` and the rollover in `src/template.ts`; both exist to keep
  local time out of the output.

## A note sorts or deduplicates oddly in Anki

`sfld` and `csum` come from the first field with its HTML stripped, and Anki
recomputes both on import. A mismatch between what this package writes and what
Anki computes means the stripper port disagrees with `rslib/src/text.rs`.

Checks:

- Run the field through `stripHtmlPreservingMediaFilenames` and compare against
  `test/fixtures/anki-stripped-fields.json`, which holds 315 cases generated by
  Anki 26.8.1 itself.
- Remember the stripper is not trimming, and media filenames keep a space on
  each side.
- Entity decoding is all-or-nothing: one bare `&` anywhere leaves the entire
  string undecoded. That is Anki's behavior, not a bug here.

Fix:

- Add the failing case to the fixture from a real Anki collection, then correct
  the port. Do not adjust the port to match intuition — order of operations in
  it is load bearing.

## A media file does not appear on a card

Checks:

- `addMedia` buffers the file but never verifies that a card references it, and
  `addCard` never verifies that a referenced file was added. Confirm the
  filename in the card HTML matches the one passed to `addMedia` exactly.
- Unzip the `.apkg` and read the `media` entry; it maps stringified indices to
  filenames, and each index is a real entry in the archive.

Fix:

- Correct whichever side of the filename pair is wrong.

## `lint` passes locally but CI reports type-aware failures

Checks:

- The pre-commit hook lints staged files **without** `--type-aware` for speed;
  only pre-push and `pnpm run lint` run the full set.
- Confirm `oxlint-tsgolint` is installed. Without it the type-aware rules
  silently do not run rather than erroring.

Fix:

- Run `pnpm run lint` directly before pushing.
